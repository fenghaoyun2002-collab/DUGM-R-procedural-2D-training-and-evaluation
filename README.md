# DUGM-R: procedural 2D training and evaluation

Companion code for **“DUGM-R: Uncertainty-Aware Dynamic Grid Mapping and Risk-Triggered Recovery for Learned Local Navigation.”**

This directory contains the complete **2D training pipeline** for the two components of DUGM-R:

1. **DUGM nominal policy** (`π_nom`): a PPO policy trained on a Dynamic Uncertainty Grid Map (DUGM).
2. **DUGM-R recovery**: deterministic nominal rollouts, an H40 Risk Value Function (RVF), validation threshold selection, a recovery PPO policy (`π_rec`), and risk-triggered hysteresis switching.

The policies are trained in the 2D environment. The Isaac Sim benchmark is an **evaluation setting**, not a training dependency: every public training command runs without it. The benchmark is not included at present because the full benchmark is large and contains official NVIDIA assets that are inconvenient to release in this repository. There are no pretrained checkpoints, rollout datasets, thresholds, or result tables here; users train and test their own models.

## Install and smoke run

Requires Python 3.11 or newer. From this directory:

```bash
python -m pip install -e '.[dev]'
dugm-r smoke --output outputs/smoke
python -m pytest -q
```

The smoke command starts with no model and performs a short PPO update, three nominal rollout episodes, one RVF update and threshold selection, one recovery PPO update, and one test scene for each method. It also creates observation, RVF, and trajectory plots. Its scores have no research meaning.

## Full training sequence

Run in this order. `outputs/` is ignored by Git.

```bash
dugm-r train-nominal --output outputs/run01/nominal
dugm-r collect-nominal-rollouts \
  --nominal outputs/run01/nominal/nominal_best.zip \
  --output outputs/run01/rollouts
dugm-r train-rvf \
  --rollouts-manifest outputs/run01/rollouts/rollouts_manifest.json \
  --output outputs/run01/rvf
dugm-r train-recovery \
  --nominal outputs/run01/nominal/nominal_best.zip \
  --rvf outputs/run01/rvf/rvf_h40.pt \
  --thresholds outputs/run01/rvf/rvf_h40_thresholds.json \
  --output outputs/run01/recovery
```

The default configuration follows the selected 2D method settings: six nominal PPO curriculum stages totalling 9.5 million steps with 16 environments; 50,000 deterministic rollout episodes; H40 RVF with weighted BCE for 8 epochs; and 1.25 million recovery PPO steps with 16 environments. The last nominal scene stage and its fixed validation protocol are replaced by independent procedural scenes. Recovery training starts from scratch because no private warm-start checkpoint is distributed. These are full research-scale defaults and require substantial compute and disk space. You may pass `--config path/to/config.yaml` to each command; paths inside a config are relative to that config file.

The outputs use stable names: `nominal_best.zip`, `rollouts_manifest.json`, `rvf_h40.pt`, `rvf_h40_thresholds.json`, and `recovery_best.zip`. Local manifests record hashes and configuration provenance. Missing inputs are errors; commands do not search the original research repository for fallback weights or data.
Training and rollout commands require a new empty output directory, so reruns cannot silently mix artifacts from different configurations.

To continue recovery PPO from a checkpoint generated by your own earlier recovery run, add `--warm-start-recovery path/to/recovery_best.zip` to `train-recovery`. Its hash is recorded in the local manifest. The default starts from scratch; no private warm-start checkpoint is supplied.

## 2D testing and visualization

The `procedural_2d_test` scene IDs and seeds in `eval_2d.yaml` are fixed and separate from training validation seeds. The same scenes are used for both methods.
Nominal training draws scene seeds below 1,000,000, recovery training uses 1,000,000–1,999,999, validation starts at 2,000,000, public testing starts at 3,000,000, and RVF rollout episodes start at 4,000,000.

```bash
dugm-r eval-2d --method dugm_nominal \
  --nominal outputs/run01/nominal/nominal_best.zip --output outputs/run01
dugm-r render-2d --method dugm_r \
  --nominal outputs/run01/nominal/nominal_best.zip \
  --rvf outputs/run01/rvf/rvf_h40.pt \
  --thresholds outputs/run01/rvf/rvf_h40_thresholds.json \
  --recovery outputs/run01/recovery/recovery_best.zip \
  --output outputs/run01
dugm-r render-curriculum --output outputs/run01/visualization/curriculum
dugm-r render-observation --output outputs/run01/visualization/observation
dugm-r render-rvf --rvf outputs/run01/rvf/rvf_h40.pt \
  --output outputs/run01/visualization/rvf
```

`render-observation` saves the exact float32 DUGM tensor delivered to the policy, its four-value state, and diagnostic static and dynamic cost arrays. `render-rvf` defaults to a fixed public test scene; `--level`, `--seed`, and `--state d b v w` can select a scene and a normalized state. It fixes the grid and varies bearing and previous linear command around that state. Its colour scale is an **uncalibrated risk score**, not a calibrated collision probability. `render-2d` saves per-scene outcome JSON and trajectory/risk plots. The `eval-2d` command saves JSON without plots.

## Observation and policy contract

- A 360-ray LiDAR scan and scan pose/time feed clustering, association, Kalman tracking, and a 4.0 s uncertainty-aware prediction sampled every 0.2 s.
- `dugm` is `float32[2,64,64]` over 16 m × 16 m at 0.25 m/cell: `[U_t, C_t]`, where `U_t` is observed-unsafe and `C_t = max(S_t, D_t)` combines visible scan endpoints with predicted dynamic cost. `C_t` stays continuous through rollout storage.
- `state` is `float32[4]`: normalized goal distance, goal bearing, previous **executed** linear command, and previous executed angular command.
- The normalized action is `float32[2]` in `[-1,1]²`, mapped to forward speed `[0,0.22]` m/s and yaw rate `[-2.84,2.84]` rad/s at 0.1 s control steps with acceleration and wheel-speed constraints.
- Simulator actor truth advances scenes and judges collisions; it is not an input to the DUGM observation or RVF. The nominal reward has no separate action-conditioned velocity-obstacle term.

## Configuration map

| File                         | Purpose                                            | Main defaults                                                          |
| ---------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| `curriculum_2d.yaml`       | Procedural levels, LiDAR, reward, DUGM observation | Levels 0–10; independent high-difficulty stages                       |
| `dugm_estimator.yaml`      | Scan clustering and tracking                       | 360 rays, 64 × 64 grid, Kalman/Hungarian association                  |
| `nominal_train_2d.yaml`    | `π_nom` PPO course                              | 6 stages, 16 envs, 9.5M steps, dual-branch CNN                         |
| `nominal_rollouts_2d.yaml` | H40 data collection                                | 50,000 episodes, episode-level 70/15/15 split, float32 DUGM            |
| `rvf_h40.yaml`             | RVF and validation threshold                       | 40 steps, 8 epochs, weighted BCE, hysteresis return fraction 0.5       |
| `recovery_train_2d.yaml`   | `π_rec` online switching PPO                    | 1.25M steps, 16 envs, 4-step minimum recovery and 3-step release dwell |
| `eval_2d.yaml`             | Fixed public 2D test scenes                        | Distinct test seeds for both methods                                   |
